# センサのテスト設計（共通）

センサの仕様の要求（`SEN-<センサ>-<番号>`、[センサの共通仕様](README.md) 8 章）を、**どこで確かめるか**を決めます。
センサごとのテスト設計（`<センサ>/test-design.md`）は、この文書の決まりに従います。

ロータ由来の周期的な IMU の観測外乱は、[振動の仕様](vibration/README.md)と[テスト設計](vibration/test-design.md)に分け、要求の番号 `SEN-VIB-*` と試験の番号 `T-VIB-*` を使います。センサのノイズ・ドリフトの試験とは区別します。

## 1. 確かめ方の種類

要求ごとに、次のどれで確かめるかを決めます。1 つの要求を、複数の段で確かめてもかまいません。

| 記号 | 確かめ方 | 何を使うか | 向いている要求 |
|---|---|---|---|
| R | レビュー | 文書・コード・設定を人が読んで、チェックリストで確かめる | 試験にしにくいもの（構造、命名、「〜しない」、書き方の決まり） |
| U1 | 関数の単体試験 | 共通の部品（回転、Gauss-Markov、丸め、頭打ち、遅れ、平均、種の作り方）を、1 つずつ試験する | 式・境界・丸めの決まり |
| U2 | センサの単体試験 | センサに作った真値を入れ、処理の順番を通した出力を確かめる | 処理の順番、統計の性質、既定値、乱数 |
| U3 | 設定の試験 | drone_config を読み込み、正しい値・エラーを確かめる | 設定の書き方、既定値、エラーの条件 |
| I1 | 機体の試験 | MuJoCo で機体を動かし、センサの出力を物理の真値と比べる | 真値の取り方、取り付けの位置の効き方 |
| I2 | Control Link の飛行試験 | PX4・ArduPilot の制御と推定を Control Link で動かし、飛び方を比べる | 自動操縦と合わせたときのふるまい |
| S | SITL の飛行試験 | PX4 SITL・ArduPilot SITL で飛ばし、飛び方を比べる | 自動操縦の本物の処理を通したふるまい |

**選び方**：できるだけ下の段（R・U1）ではなく、要求を直接確かめられる一番軽い試験の段を選びます。
U1・U2 で確かめられるものを、I2・S だけで確かめることはしません（飛ばしてずれても、原因が分からないため）。
I2・S は、「自動操縦と合わせたときにどうなるか」という、飛ばさないと分からない要求だけに使います。

## 2. 試験の番号

試験には `T-<センサ>-<段>-<3 けた>` の番号を振ります。例：`T-GYR-U2-010`。
1 つの試験が複数の要求を確かめるときは、試験の表に要求の番号をすべて書きます。

## 3. 期待値の作り方

**実装の式をなぞらない**ことを守ります。実装と同じ式で期待値を作ると、式が間違っていても試験は通ってしまいます。

| やり方 | 例 |
|---|---|
| 手で計算できる例 | `yaw = 90` なら、機体の +x はセンサの −y |
| 物理の答え | 水平に止まっていれば比力は (0, 0, −9.80665)、自由落下なら 0 |
| 別の計算の仕組み | センサの位置の速度を、MuJoCo の site（MJCF に置いた点）の速度と比べる |
| 自動操縦のソースの式 | PX4 の `Dcmf(OFF) · rotation(ROT)` で R に戻るか |
| 出力の実測 | 標準偏差を、出力の値から数えて確かめる（設定値をそのまま読まない） |

## 4. 判定の基準

### 4.1 決まった値の試験（U1・U2・U3・I1）

- 浮動小数の比較は、相対 1e-9 または絶対 1e-12 のどちらか大きい方の幅で比べます。MuJoCo を通すもの（I1）は、物理の刻みの誤差を見込んで、試験ごとに幅を書きます。
- 丸めと頭打ちは、ちょうどの値（境界の上・下・ちょうど中間）を必ず入れます。

### 4.2 統計の試験（U1・U2）

| 確かめること | サンプル数 | 合格の幅 |
|---|---|---|
| 平均 | N = 20,000 | 平均の絶対値 < 4σ/√N |
| 標準偏差 | N = 20,000 | 設定値の ±3% 以内 |
| 2 つの列が独立 | N = 20,000 | 相関係数の絶対値 < 0.03 |
| Gauss-Markov の分散と相関 | 相関時間 τ の 5,000 倍以上の長さ（となりの値が強く似ているので、長さで数を稼ぐ） | 分散が σ² の ±10% 以内、遅れ τ の自己相関が e⁻¹ ± 0.05 |

- 乱数の種は試験ごとに固定し、試験が毎回同じ結果になるようにします。
- 合格の幅は、正しい実装が偶然落ちる確率が十分小さくなるように決めています（標準偏差の ±3% は、N = 20,000 で約 6σ に当たります）。

### 4.3 飛行の試験（I2・S）

実時間で動かすと、同じ設定でも飛び方は少しずつ変わります。そこで、**1 回の飛行では判定しません**。
また、**統計のばらつき**（偶然の揺れ）と、**工学的に許せる差**（この差なら問題ない、という幅 δ）を分けて判定します。
ばらつきだけで判定すると、ばらつきがほぼ 0 のときは許せる差まで 0 になり、ばらつきが大きいときは実際には困る差まで通ってしまうためです。

1. **飛ばす**：基準の設定（例：取り付け位置姿勢なし）と試す設定で、同じ飛行をそれぞれ 5 回以上飛ばす。
2. **差を測る**：指標（4.3.1）ごとに、試す飛行の平均 − 基準の平均を求め、その 95% 信頼区間（2 群の平均の差の t 区間）を求める。
3. **判定する**：
   - 「同じように飛ぶ」：差の 95% 信頼区間が、すべて ±δ の中に入る。
   - 「ずれる」：差の 95% 信頼区間が、すべて ±δ の外にある（その向きに δ を超えている）。
   - どちらとも言えない（区間が δ をまたぐ）：回数を増やして（1 回ずつ、最大 20 回まで）やり直す。20 回でも決まらなければ失敗とし、理由を調べる。
4. 起動で止まった・指令が届かないなど、飛行そのものが成り立たなかった回は、判定に入れずに数えて報告する（続けて 2 回あれば、その試験は失敗）。
5. 「ずれる」側の試験では、機体が姿勢を保てずに飛べなかったことも「ずれる」に含める。

#### 4.3.1 指標と許せる差 δ の既定値

| 指標 | 意味 | δ の既定値 |
|---|---|---|
| 位置の誤差の二乗平均 | 目標の経路からの水平・垂直の誤差 | 0.05 m と、基準の平均の 10% の大きい方 |
| 姿勢の誤差の最大 | ロール・ピッチの目標からの誤差の最大 | 1° |
| かかった時間 | 離陸の指令から着地まで | 0.5 秒 |

- 位置と姿勢の指標を測る区間は、**離陸の指令から、着陸の指令まで**です。着陸（地面との接触）は、取り付けやセンサの試験の対象にしません。
  地面に当たる瞬間は、機体が地面の上で水平のまま制御の目標の姿勢だけが大きく動くことがあり、空中の飛び方を表さないためです。
- かかった時間の終わりの着地は、真値の高さと上下の速度で決めます（地面からの高さ 0.05 m 以下、上下の速さ 0.1 m/s 以下が 0.2 秒続いた最初の時刻）。

- 試験ごとに、既定値と違う δ を使うときは、試験の表に値と理由を書きます（例：「ほぼ同じように飛ぶ」の試験は、物理として残る差の見積もりから δ を決める）。
- δ は、試験を走らせる前に決めます。結果を見てから δ を変えてはいけません。

### 4.4 既定値の互換

これまでとの互換は、ビルドの切り替えが OFF のときだけ約束します（共通仕様 7.6）。

- **OFF**：既存の設定（新しい項目を書かない設定）で、変更の前と後の出力を比べます。同じ機体・同じ飛行・同じ乱数の種で、決まった真値の列を入れ、
  センサの出力が**ビット単位で一致**することを確かめます。変更の前の出力は、基準のデータとして残します。
- **ON**：これまでの設定が読めて、エラーにならずに値が出ることだけを確かめます。出力は比べません（非互換）。
- 仕様で既定の動きを変えたもの（例：GPS の進行方向の無効）は、その差だけを例外として試験の表に書きます。

## 5. ビルドと実行

- 単体試験（U1・U2・U3）と機体の試験（I1）は、Debug と Release の両方で通すこと。Release で試験の判定が消えないよう、判定は試験の枠組み（gtest の `EXPECT_*`・`ASSERT_*`）で書き、`assert` は使いません。
- 飛行の試験（I2・S）は、試験の手順と判定のスクリプトを残し、だれが実行しても同じ判定になるようにします。

## 6. レビューのチェックリスト（R）

レビューで確かめる要求は、次の観点でまとめて確かめます。センサごとのテスト設計に、どの要求をどの観点で見るかを書きます。

| 観点 | 確かめること |
|---|---|
| R-01 共通の部品 | 回転・Gauss-Markov・丸め・頭打ちを、どのセンサも同じ 1 つの関数で使っている（コピーした式がない） |
| R-02 単位 | 設定・内部・出力の単位が仕様どおりで、換算が 1 か所にまとまっている |
| R-03 「しない」こと | 仕様で「しない」と決めたこと（上に伝えない、補正しない など）を、コードがしていない |
| R-04 設定の渡し方 | 自動操縦の設定を、決めた場所（アダプターのパラメータ、SITL の起動のパラメータ）に、起動の前に渡している |
| R-05 文書 | 公開の文書に、非公開の文書へのリンク・issue の番号・実装の状況が書かれていない |
| R-06 物理に頼らない | センサの計算のコードが、MuJoCo・箱庭の通信・自動操縦のコードを読み込んでいない。必要な値はインタフェースの入力で受け取っている |
